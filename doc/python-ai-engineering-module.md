### Level 1 · Foundation | Senior Agentic AI Engineer Roadmap

## How This Module Works

You already know how to build production software in .NET. This module does **not** teach you programming from scratch — it teaches you **Python through the lens of your existing knowledge**, and immediately anchors every concept to how it shows up in real AI engineering codebases.

### Two Tracks, Taught Together

| Track A | Track B |
|---|---|
| Python the language (syntax, concepts, idioms) | Python for AI Engineering (how those concepts appear in LLM/agent code) |

Every section = concept + C# anchor + real AI code example + pitfalls + exercise.

### Per-Section Learning Flow

```
1. CONCEPT      — explained with .NET as the anchor         (5 min)
2. CODE         — real examples, not toy snippets           (10 min)
3. AI ANCHOR    — where this shows up in LLM/agent code     (3 min)
4. PITFALLS     — what goes wrong, how seniors avoid it     (3 min)
5. EXERCISE     — you write code; mentor reviews it         (20–40 min)
6. CHECKPOINT   — 2–3 quick questions before moving on
```

### Ground Rules
- We go **one section at a time** — you say when to move on
- Every exercise is reviewed like a pull request — specific, honest feedback
- C# equivalents are shown wherever the concept is genuinely different
- No hand-wavy explanations — if something works a certain way, we explain *why*

### Estimated Time
- **Total:** 60–80 hours of focused study + exercises
- At 10 hrs/week → 6–8 weeks
- At 15 hrs/week → 4–5 weeks

### Section 3.1 — Comprehensions and Generators (Lazy Evaluation)

| Concept | C# Equivalent | Python |
|---|---|---|
| List comprehension | `.Select().ToList()` | `[f(x) for x in items]` |
| Filtered comprehension | `.Where().Select().ToList()` | `[f(x) for x in items if cond]` |
| Dict comprehension | no direct LINQ | `{k: v for k, v in pairs}` |
| Set comprehension | no direct LINQ | `{x for x in items}` |
| Generator expression | `IEnumerable<T>` (lazy) | `(f(x) for x in items)` |
| `yield` keyword | `yield return` | `yield value` |
| Generator function | iterator method | `def gen(): yield x` |
| `yield from` | no direct equivalent | delegates to another generator |
| Async generator | `IAsyncEnumerable<T>` | `async def gen(): yield x` |

**AI engineering connection:**
- Chunking pipeline: `(chunk for doc in docs for chunk in chunk_doc(doc))`
- Token streaming: async generator yielding each token
- Lazy eval dataset loading: generator over CSV rows
- Batch processing: `islice(chunks, batch_size)` for embedding batches

**Exercise:** Build a lazy document chunking pipeline using generators — processes a large text file without loading it into memory.

### Section 3.4 — Error Handling and Exceptions

## UNIT 5 — Async Python

**Goal:** Write correct, performant async Python. Understand every failure mode. This is the most critical unit.

---

### Section 5.1 — Why Async? I/O-Bound vs CPU-Bound

| Type | Examples | Best tool |
|---|---|---|
| **I/O-bound** | LLM API calls, DB queries, HTTP requests, file reads | `asyncio` |
| **CPU-bound** | Token counting, text parsing, numpy ops, ML inference | `multiprocessing` / `ProcessPoolExecutor` |
| **Mixed** | Fetch documents (I/O) then embed (CPU then I/O) | `asyncio` + `to_thread` for CPU parts |

**Key insight:** A single Python event loop can handle thousands of concurrent LLM API calls because it's just waiting for network responses — no CPU needed while waiting.

---

### Section 5.2 — The Event Loop — How It Actually Works

```
Event Loop Cycle:
┌─────────────────────────────────────────┐
│  1. Check for completed I/O operations  │
│  2. Resume coroutines waiting on them   │
│  3. Run all ready callbacks             │
│  4. Poll for new I/O with epoll/kqueue  │
│  5. Go back to step 1                   │
└─────────────────────────────────────────┘

When you `await something`:
  → Current coroutine is SUSPENDED (not blocked)
  → Event loop picks up another ready coroutine
  → When the I/O completes, yours is resumed
```

**Critical insight:** `await` is cooperative — you voluntarily yield control. If you call `time.sleep(5)` instead of `await asyncio.sleep(5)`, you block the entire loop — all other coroutines freeze for 5 seconds.

---

### Section 5.3 — async/await Basics

| Coroutine object | `Task<T>` (not started yet) | coroutine (not started yet) |

### Section 5.4 — Concurrency Primitives

| Primitive | C# Equivalent | When to Use |
|---|---|---|
| `asyncio.gather()` | `Task.WhenAll()` | Run multiple coroutines concurrently |
| `return_exceptions=True` | no direct equiv | Don't cancel all when one fails |
| `asyncio.TaskGroup` | no direct equiv | Structured concurrency — 3.11+ |
| `asyncio.Semaphore(n)` | `SemaphoreSlim(n)` | Bound to N concurrent operations |
| `asyncio.Lock()` | `SemaphoreSlim(1)` | Mutual exclusion |
| `asyncio.Event()` | `ManualResetEventSlim` | Signal between coroutines |
| `asyncio.Queue()` | `Channel<T>` | Producer/consumer pipelines |
| `asyncio.wait()` | `Task.WhenAny()` | First-completed pattern |

**The most important pattern in AI engineering — bounded concurrent LLM calls:**
```python
semaphore = asyncio.Semaphore(10)  # max 10 concurrent calls

async def call_with_limit(prompt: str) -> str:
    async with semaphore:           # blocks if 10 already running
        return await call_llm(prompt)

results = await asyncio.gather(
    *[call_with_limit(p) for p in prompts],
    return_exceptions=True,
)
```

| Concept | C# | Python |
|---|---|---|

### Section 5.6 — Async Generators and Streaming

| Concept | C# | Python |
|---|---|---|
| Async generator function | `IAsyncEnumerable<T>` method | `async def gen(): yield value` |
| Consuming async generator | `await foreach` | `async for item in gen():` |
| Async context manager from generator | no direct equiv | `@asynccontextmanager` |
| SSE / chunked HTTP response | `IAsyncEnumerable` over HTTP | `async for line in response.aiter_lines():` |

**Token streaming — the pattern used in every AI app:**
```python
async def stream_tokens(prompt: str) -> AsyncGenerator[str, None]:
    async with httpx.AsyncClient() as client:
        async with client.stream("POST", url, json={...}) as response:
            async for line in response.aiter_lines():
                if token := parse_sse_line(line):
                    yield token   # one token at a time, as it arrives

# FastAPI SSE endpoint:
async def sse_response(prompt: str):
    async for token in stream_tokens(prompt):
        yield f"data: {token}\n\n"
```

### Section 5.7 — Common Async Mistakes and How to Avoid Them

| Mistake | Why It's Dangerous | Fix |
|---|---|---|
| `time.sleep(n)` in `async def` | Freezes the ENTIRE event loop | `await asyncio.sleep(n)` |
| Sync SDK call in `async def` | Same — stalls every other coroutine | `await asyncio.to_thread(sync_fn, args)` |
| No concurrency bound | 429 rate limits, connection pool exhaustion, OOM | `asyncio.Semaphore(n)` |
| Swallowing `CancelledError` | Task never actually cancels; cleanup skipped | Always `raise` in `except CancelledError` |
| Creating tasks without storing reference | GC collects the task mid-execution | Store in a `set`; discard on done |
| Nested `asyncio.run()` | `RuntimeError: This event loop is already running` | Only call `asyncio.run()` at the top-level entry point |
| CPU-heavy work on the event loop | Starves all other coroutines | `await asyncio.to_thread(cpu_fn)` or `ProcessPoolExecutor` |
| Not handling `return_exceptions=True` | One failure cancels all parallel calls | Always use `return_exceptions=True` in `gather` |

│  - MockSource (for tests)     ├── url: str               │
│                               ├── content: str | None    │
└───────────────────────────────├── error: str | None      │
                                ├── status_code: int | None│
                                ├── latency_ms: float      │
                                └── fetched_at: datetime   │

### Security Considerations

| Risk | Mitigation |
|---|---|
| SSRF (Server-Side Request Forgery) | Validate URLs against allowlist; reject private IP ranges (10.x, 192.168.x, 127.x, 169.254.x) |
| Response bomb (huge response) | Enforce max response size in bytes; abort oversized responses |
| Secret leakage in logs | Redact `Authorization` headers and API keys from structlog output |
| Content-type confusion | Validate `Content-Type` header matches expected MIME type |
| Redirect abuse | Limit redirect depth; validate redirect targets against allowlist |
